# GitHub Fork 협업 가이드

## 1. 목적

이 문서는 원본 GitHub 저장소를 Fork한 뒤 원본 저장소를 `upstream`으로 등록하고, 개인 Fork에서 별도 브랜치를 생성하여 Pull Request를 만드는 절차만 설명한다.

특정 작업, Issue, 기능, 파일 또는 담당자에 대한 예시는 포함하지 않는다.

전체 흐름은 다음과 같다.

```text
원본 저장소 Fork
→ 개인 Fork Clone
→ 원본 저장소를 upstream으로 등록
→ upstream/main 최신화
→ 개인 Fork에서 작업 브랜치 생성
→ 변경사항 커밋
→ 개인 Fork에 브랜치 Push
→ 원본 저장소 main으로 Pull Request 생성
```

---

## 2. 저장소와 브랜치 구조

```text
원본 저장소(upstream)
└── main

개인 Fork 저장소(origin)
├── main
└── <작업-브랜치>
```

- `upstream`: 원본 저장소를 가리키는 원격 이름
- `origin`: 개인 Fork 저장소를 가리키는 원격 이름
- `main`: 원본 저장소의 기본 브랜치
- `<작업-브랜치>`: 개인 Fork에서 생성하는 별도 브랜치

Fork 방식에서는 변경사항을 원본 저장소의 `main`에 직접 Push하지 않는다.

원본 저장소에 작업 브랜치를 별도로 만들 필요도 없다. 개인 Fork의 작업 브랜치를 원본 저장소의 `main`으로 보내는 Pull Request를 생성하면 된다.

---

## 3. 원본 저장소 Fork

1. GitHub에서 원본 저장소에 접속한다.
2. 화면 우측 상단의 `Fork`를 선택한다.
3. Fork를 생성할 개인 계정 또는 조직을 선택한다.
4. 저장소 이름을 확인한다.
5. 필요한 경우 `Copy the main branch only`를 선택한다.
6. `Create fork`를 선택한다.

Fork가 완료되면 개인 계정 아래에 원본 저장소의 복사본이 생성된다.

```text
원본 저장소:
<원본-소유자>/<저장소명>

개인 Fork:
<개인-GitHub-ID>/<저장소명>
```

---

## 4. 개인 Fork Clone

원본 저장소가 아니라 개인 Fork 저장소를 Clone한다.

HTTPS 방식:

```bash
git clone https://github.com/<개인-GitHub-ID>/<저장소명>.git
cd <저장소명>
```

SSH 방식:

```bash
git clone git@github.com:<개인-GitHub-ID>/<저장소명>.git
cd <저장소명>
```

Clone 직후 원격 저장소를 확인한다.

```bash
git remote -v
```

예상 구조:

```text
origin  https://github.com/<개인-GitHub-ID>/<저장소명>.git (fetch)
origin  https://github.com/<개인-GitHub-ID>/<저장소명>.git (push)
```

이때 `origin`은 개인 Fork를 가리킨다.

---

## 5. 원본 저장소를 upstream으로 등록

개인 Fork를 최신 원본 저장소와 동기화하려면 원본 저장소를 `upstream`이라는 이름으로 등록한다.

HTTPS 방식:

```bash
git remote add upstream \
  https://github.com/<원본-소유자>/<저장소명>.git
```

SSH 방식:

```bash
git remote add upstream \
  git@github.com:<원본-소유자>/<저장소명>.git
```

등록 결과를 확인한다.

```bash
git remote -v
```

정상 구조:

```text
origin    https://github.com/<개인-GitHub-ID>/<저장소명>.git (fetch)
origin    https://github.com/<개인-GitHub-ID>/<저장소명>.git (push)
upstream  https://github.com/<원본-소유자>/<저장소명>.git (fetch)
upstream  https://github.com/<원본-소유자>/<저장소명>.git (push)
```

확인 사항:

- `origin`이 개인 Fork를 가리키는지 확인한다.
- `upstream`이 원본 저장소를 가리키는지 확인한다.
- 두 원격 저장소가 반대로 등록되지 않았는지 확인한다.

원격 URL을 잘못 등록했다면 다음 명령으로 수정한다.

```bash
git remote set-url origin <개인-Fork-URL>
git remote set-url upstream <원본-저장소-URL>
```

## 6. upstream/main 최신화

새 브랜치를 만들기 전에 원본 저장소의 최신 `main`을 가져온다.

```bash
git switch main
git fetch upstream
git merge --ff-only upstream/main
```

명령의 의미:

1. `git switch main`: 로컬 `main`으로 이동한다.
2. `git fetch upstream`: 원본 저장소의 최신 상태를 가져온다.
3. `git merge --ff-only upstream/main`: 로컬 `main`을 원본 `main`과 동일한 최신 상태로 이동한다.

개인 Fork의 `main`도 최신화한다.

```bash
git push origin main
```

전체 명령:

```bash
git switch main
git fetch upstream
git merge --ff-only upstream/main
git push origin main
```

`--ff-only`에서 실패하면 로컬 `main`에 원본 저장소에 없는 커밋이 있을 수 있다. 이 경우 강제 Push하지 말고 다음 명령으로 상태를 먼저 확인한다.

```bash
git status
git log --oneline --graph --decorate --all
```

---

## 7. 개인 Fork에서 브랜치 생성

브랜치는 최신화된 로컬 `main`에서 생성한다.

```bash
git switch main
git switch -c <브랜치명>
```

예시 형식을 사용할 경우:

```text
<종류>/<짧은-설명>
```

브랜치가 정상적으로 생성되었는지 확인한다.

```bash
git branch --show-current
git status
```

중요 원칙:

- `main`에서 직접 변경하지 않는다.
- 작업마다 별도의 브랜치를 만든다.
- 이미 병합된 브랜치를 재사용하지 않는다.
- 브랜치는 최신 `upstream/main`을 기준으로 만든다.
- 작업 브랜치는 개인 Fork에만 Push하면 된다.

---

## 8. 변경사항 커밋

변경 전 현재 브랜치를 확인한다.

```bash
git branch --show-current
```

변경된 파일을 확인한다.

```bash
git status
git diff
```

필요한 파일만 Stage한다.

```bash
git add <파일-또는-경로>
```

Stage된 내용을 확인한다.

```bash
git diff --cached
```

커밋한다.

```bash
git commit -m "<커밋-메시지>"
```

확인 사항:

- 현재 브랜치가 `main`이 아닌지 확인한다.
- 불필요한 파일이 포함되지 않았는지 확인한다.
- 인증 정보나 환경 파일이 포함되지 않았는지 확인한다.
- 커밋 전에 `git diff --cached`를 확인한다.

---

## 9. 개인 Fork에 브랜치 Push

최초 Push에서는 로컬 브랜치와 개인 Fork의 원격 브랜치를 연결한다.

```bash
git push -u origin <브랜치명>
```

여기서 `origin`은 개인 Fork 저장소다.

최초 Push 이후 같은 브랜치에서는 다음 명령을 사용할 수 있다.

```bash
git push
```

Push 결과를 확인한다.

```bash
git status
git branch -vv
```

GitHub의 개인 Fork 저장소에서도 해당 브랜치가 생성되었는지 확인한다.

---

## 10. Pull Request 생성 방향

Pull Request는 다음 방향으로 생성한다.

```text
Base repository: 원본 저장소
Base branch: main
Head repository: 개인 Fork
Compare branch: 개인 Fork의 작업 브랜치
```

도식:

```text
개인 Fork의 <작업-브랜치>
              ↓ Pull Request
원본 저장소의 main
```

반대 방향으로 생성하지 않도록 주의한다.

---

## 11. GitHub 화면에서 Pull Request 생성

1. 개인 Fork에 작업 브랜치를 Push한다.
2. GitHub에서 `Compare & pull request`를 선택한다.
3. `base repository`가 원본 저장소인지 확인한다.
4. `base`가 `main`인지 확인한다.
5. `head repository`가 개인 Fork인지 확인한다.
6. `compare`가 개인 작업 브랜치인지 확인한다.
7. Pull Request 제목을 작성한다.
8. 변경사항과 확인 방법을 설명한다.
9. `Create pull request`를 선택한다.

Pull Request 생성 직전 반드시 다음 구조인지 확인한다.

```text
<원본-소유자>/<저장소명>:main
←
<개인-GitHub-ID>/<저장소명>:<브랜치명>
```

---

## 12. gh CLI로 Pull Request 생성

GitHub CLI를 사용하는 경우:

```bash
gh pr create \
  --repo <원본-소유자>/<저장소명> \
  --base main \
  --head <개인-GitHub-ID>:<브랜치명> \
  --title "<Pull-Request-제목>" \
  --body "<Pull-Request-설명>"
```

브라우저에서 입력하며 생성하려면 다음 명령을 사용할 수 있다.

```bash
gh pr create --web \
  --repo <원본-소유자>/<저장소명> \
  --base main \
  --head <개인-GitHub-ID>:<브랜치명>
```

생성된 Pull Request를 확인한다.

```bash
gh pr view --web
```

---

## 13. Pull Request 수정 반영

Pull Request가 열린 뒤 수정이 필요하면 동일한 로컬 브랜치에서 변경하고 다시 Push한다.

```bash
git switch <브랜치명>

# 파일 수정 후
git add <파일-또는-경로>
git commit -m "<수정-커밋-메시지>"
git push
```

같은 브랜치에 Push하면 기존 Pull Request가 자동으로 갱신된다. 새로운 Pull Request를 다시 만들 필요가 없다.

---

## 14. 작업 중 upstream/main 변경 반영

Pull Request가 병합되기 전에 원본 `main`이 변경될 수 있다.

개인 작업 브랜치에 최신 원본 내용을 반영하려면 다음 순서를 사용한다.

```bash
git fetch upstream
git switch <브랜치명>
git merge upstream/main
```

충돌이 발생하면 충돌 파일을 수정한 뒤 다음과 같이 반영한다.

```bash
git add <충돌-해결-파일>
git commit
git push
```

Rebase를 선택하는 경우:

```bash
git fetch upstream
git switch <브랜치명>
git rebase upstream/main
git push --force-with-lease
```

주의:

- Rebase에 익숙하지 않으면 merge 방식을 사용한다.
- `--force` 대신 `--force-with-lease`를 사용한다.
- 다른 사람이 함께 사용하는 브랜치에는 강제 Push하지 않는다.

---

## 15. Pull Request 병합 후 정리

Pull Request가 원본 저장소에 병합되면 로컬과 개인 Fork의 `main`을 다시 최신화한다.

```bash
git switch main
git fetch upstream
git merge --ff-only upstream/main
git push origin main
```

로컬 작업 브랜치를 삭제한다.

```bash
git branch -d <브랜치명>
```

개인 Fork의 원격 작업 브랜치를 삭제한다.

```bash
git push origin --delete <브랜치명>
```

다음 작업은 기존 브랜치를 재사용하지 않고, 최신화된 `main`에서 새 브랜치를 만든다.

## 16. 전체 명령 순서

```bash
# 개인 Fork Clone
git clone <개인-Fork-URL>
cd <저장소명>

# 원본 저장소 등록
git remote add upstream <원본-저장소-URL>
git remote -v

# 원본 main 최신화
git switch main
git fetch upstream
git merge --ff-only upstream/main
git push origin main

# 개인 Fork에서 별도 브랜치 생성
git switch -c <브랜치명>

# 변경사항 커밋
git add <파일-또는-경로>
git diff --cached
git commit -m "<커밋-메시지>"

# 개인 Fork에 작업 브랜치 Push
git push -u origin <브랜치명>

# 원본 저장소 main으로 Pull Request 생성
gh pr create \
  --repo <원본-소유자>/<저장소명> \
  --base main \
  --head <개인-GitHub-ID>:<브랜치명> \
  --title "<Pull-Request-제목>" \
  --body "<Pull-Request-설명>"
```

## 17. 최종 확인 사항

- [ ] 원본 저장소를 Fork했다.
- [ ] 개인 Fork를 Clone했다.
- [ ] `origin`이 개인 Fork를 가리킨다.
- [ ] `upstream`이 원본 저장소를 가리킨다.
- [ ] 최신 `upstream/main`을 반영했다.
- [ ] 개인 Fork에서 별도 브랜치를 생성했다.
- [ ] 변경사항을 개인 Fork의 브랜치에 Push했다.
- [ ] PR의 Base가 원본 저장소 `main`이다.
- [ ] PR의 Head가 개인 Fork의 작업 브랜치다.
- [ ] 원본 저장소 `main`에 직접 Push하지 않았다.

Fork 방식에서 작업 위치는 다음과 같다.

```text
원본 저장소: main과 Pull Request 관리
개인 Fork: 작업 브랜치 생성과 Push
Pull Request: 개인 Fork 작업 브랜치 → 원본 저장소 main
```
